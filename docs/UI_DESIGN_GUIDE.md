# UI 设计指南

本文档记录 Wenku8 Downloader 当前 renderer 的 UI 基线，主要以 `Layout`、首页和配置页的现行实现为准

现有页面与本指南不一致时，在相关页面后续改动中逐步收敛，不为统一样式单独进行无关重构

## 1. 产品视觉定位

整体方向是安静、清晰、可靠的桌面书库工具

- 内容优先，先呈现当前任务、状态和下一步操作
- 使用稳定的左侧导航和右侧内容区，不采用营销落地页布局
- 以浅灰背景、白色内容表面、蓝色强调和低对比边框构成主要视觉
- 通过留白、字号、对齐和柔和分隔建立层级
- 不使用紫色渐变、玻璃拟态、霓虹光效或无意义的数据面板
- 页面优化是改善信息层级与操作效率，不等同于单纯删减内容

## 2. 当前应用壳

应用壳由 `src/renderer/src/components/Layout.tsx` 提供

| 区域 | 当前样式 |
| --- | --- |
| 应用窗口 | `h-screen`，背景使用 `apple-bg` |
| 侧边栏 | 固定宽度 220px，白色背景，右侧使用 `apple-border-medium` |
| 品牌区 | 40px 应用图标，中文名称与英文副标题 |
| 导航项 | 20px 图标，15px 文字，8px 圆角 |
| 当前导航 | `apple-accent-light` 浅蓝底，蓝色图标与文字 |
| 内容区 | 独立纵向滚动，默认内边距 32px |
| 版本号 | 固定在侧边栏底部，使用弱化文字色 |

导航只负责页面切换，内容页不重复展示侧边栏已有的入口

## 3. 内容宽度与页面层级

- 首页主体使用 `max-w-5xl`
- 配置页登录区域使用 `max-w-4xl`
- 下载与日志设置使用 `max-w-3xl`
- 搜索、详情和下载历史根据内容自然占宽，不强制铺满窗口
- 页面分区通常使用 32px 垂直间距
- 普通内容组之间使用 16–24px 内部间距
- 页面只保留一个最高视觉等级的标题
- 同一区域只设置一个最高强调等级的动作

首页允许使用约 30px 的展示标题，其他功能页标题以 24px 为主，分区标题使用 16–18px

检索和下载历史页当前保留标题下方的 44px 蓝色短线，首页与配置页依靠容器和标签层级，不重复添加该装饰

## 4. 颜色系统

颜色以 `tooling/tailwind.config.js` 中的 `apple-*` 令牌为唯一基线

| 令牌 | 当前值 | 用途 |
| --- | --- | --- |
| `apple-bg` | `#f5f5f7` | 窗口背景、浅色图标底 |
| `apple-card` | `#ffffff` | 内容表面、列表和输入区域 |
| `apple-accent` | `#0071e3` | 主动作、当前状态、链接和焦点 |
| `apple-accent-light` | `rgba(0,113,227,0.08)` | 选中态、浅色按钮、步骤序号 |
| `apple-heading` | `#1d1d1f` | 标题和主要文字 |
| `apple-body` | `#424245` | 正文 |
| `apple-secondary` | `#86868b` | 次要信息 |
| `apple-tertiary` | `#aeaeb2` | 占位符、弱提示和版本号 |
| `apple-border-subtle` | `rgba(0,0,0,0.06)` | 分组边界和列表分隔 |
| `apple-border-medium` | `rgba(0,0,0,0.08)` | 应用壳边界 |
| `apple-border-input` | `rgba(0,0,0,0.1)` | 输入框和可操作控件边界 |

成功、警告和错误分别使用绿色、琥珀色和红色，但不能只依赖颜色表达状态，必须同时提供文字或图标

## 5. 字体与文案

当前字体栈为系统字体：`-apple-system`、`BlinkMacSystemFont`、`SF Pro Text`、`PingFang SC`、`Microsoft YaHei`

| 内容 | 当前字号与字重 |
| --- | --- |
| 首页主标题 | 30px，粗体 |
| 功能页标题 | 24px，粗体 |
| 分区标题 | 18px，半粗体 |
| 卡片或字段组标题 | 14–16px，半粗体 |
| 正文、字段标签、按钮 | 14px 为主 |
| 密集元数据 | 11–12px，仅用于书籍状态、时间和次要统计 |

文案规则：

- 标题、按钮和提示直接表达用途，不重复解释同一件事
- 辅助说明尽量控制在一行或两行
- 短标签、状态和辅助文案不添加句末句号
- 书名、卷名和作品原文保留原有标点
- 索引说明明确起点，当前格式为“索引从 0 开始，0 代表第一张图”
- 自动保存成功不显示“已保存”，快速保存不显示“保存中”

## 6. 表面、圆角与分隔

### 圆角

- 输入框、普通按钮和导航项使用 8px 圆角
- 内容分组和列表容器使用 12px 圆角
- 首页主视觉区域使用 16px 圆角
- 封面图片根据尺寸使用约 6–14px 圆角
- 胶囊按钮只保留在搜索、下载等明确主动作或紧凑筛选操作中

### 边框与阴影

- 普通分组使用 1px `apple-border-subtle`
- 输入框使用 `apple-border-input`
- 边框承担分组和输入边界，不作为装饰
- 普通静态内容不使用明显阴影
- 浮层、Toast 和需要脱离当前层级的内容可以使用阴影
- 避免卡片套卡片；同类内容优先放在统一表面内

### 分隔

- 标签栏使用底部分隔线，当前标签使用 2px 蓝色下边框
- 列表使用低对比行分隔，不为每行创建大型卡片
- 首页快速入门使用两端渐隐分隔线，降低步骤之间的硬切割感
- 功能概览不使用内部十字分割，通过两列布局和留白区分内容

## 7. 按钮与交互层级

### 主动作

- 使用 `apple-accent` 实色背景和白色文字
- hover 通常降低少量透明度
- disabled 降低对比度并使用不可用光标
- 同一页面不并列多个同等级主动作

### 次要动作

- 使用 `apple-accent-light` 浅色背景，或白色背景配细边框
- 文字使用 `apple-accent` 或 `apple-secondary`
- hover 仅轻微改变背景、边框或文字颜色

### 危险与低频动作

- 使用红色文字和浅红 hover 背景
- 放入独立区域或“更多操作”菜单，不与主动作争夺层级
- 清除凭证等不可逆操作执行前必须确认

### 焦点与动效

- 可操作元素使用清晰的 `focus-visible` ring
- 常规颜色和透明度过渡为 150–200ms
- 快速入门使用低对比背景、描边和文字颜色提供 hover 反馈，不缩放正文
- 快速入门高亮使用左右对称的浅蓝渐变，边缘透明、中间保持极低对比蓝色
- 非交互内容不添加 hover，避免产生可点击错觉

## 8. 图标规范

- 同一组件组使用一致的线宽、尺寸和视觉网格
- 首页与后续新增的通用界面图标优先使用 `@tabler/icons-react`
- 常用图标尺寸为 16–20px，线宽为 1.7–1.8
- 侧边栏统一使用 20px Tabler 单色线性图标，线宽保持 1.7
- 装饰图标添加 `aria-hidden="true"`
- 仅含图标的按钮必须提供 `aria-label` 或等效可访问名称
- 品牌图标和确有专用含义的图形可以保留项目资源或内联 SVG

## 9. 表单与自动保存

- 字段始终提供可见标签，placeholder 只补充输入提示
- 输入框基线为白色或 `apple-card` 背景、8px 圆角、14px 文字
- focus 使用蓝色边框和低透明度蓝色 ring
- 校验错误靠近字段，并通过 `aria-invalid` 和 `aria-describedby` 关联
- 自动保存触发点包括选择完成、按 Enter、离开输入组或离开字段
- 保存成功保持安静，不显示成功状态或成功 Toast
- 保存失败显示就近状态，并通过 Toast 提供完整错误反馈
- 保存期间禁用会产生冲突的控件，但保留当前内容和任务上下文
- 危险数据清除不能由自动保存触发

## 10. 状态与反馈

| 状态 | 当前表现 |
| --- | --- |
| Loading | 居中 spinner 或行内 spinner，配简短状态文字 |
| Empty | 内容区居中提示，必要时补充下一步建议 |
| Error | 字段错误、`StatusAlert` 或错误 Toast |
| Success | 仅在明确操作完成且用户需要确认时使用 Toast |
| Disabled | 降低文字和背景对比度，保留原因或上下文 |
| Progress | 行内进度条、百分比和当前阶段文字 |

Toast 固定在窗口右上角，最大宽度约 24rem，使用白色表面、边框、阴影和状态圆点

## 11. 当前页面模式

### 首页

- 顶部使用白色主视觉容器，包含版本号、GitHub 入口、标题和一句产品说明
- 不重复展示侧边栏已有的检索、下载和配置快捷入口
- 快速入门是三步可点击流程，桌面端三列，较窄窗口纵向排列
- 快速入门使用渐隐分隔、左右渐变 hover、描边和文字颜色反馈
- 功能概览使用一个外层容器和两列留白布局，不为每项功能创建独立卡片
- 功能图标使用 Tabler 线性图标和浅灰底

### 检索页

- 使用书名、作者和编号三种检索标签，并按此顺序排列
- 输入区由可见标签、输入框和单一主按钮组成
- loading、error、未检索和无结果状态在原内容区切换
- 搜索结果使用响应式紧凑书籍网格，封面、书名和作者优先；最小窗口下减少列数，不压缩文字和操作

### 书籍详情页

- 顶部先提供返回入口，再展示封面、书名和作者等核心信息
- 最新章节、更新时间和字数放在统一信息表面内
- 下载区域按整本、分卷和插图分组
- 卷列表使用紧凑行和分隔线，不使用重复大型卡片

### 下载历史页

- 按进行中、失败和已完成分组
- 进行中任务展示封面、类型、进度条和当前阶段
- 已完成任务使用统一列表表面和行内次要操作
- 清空历史操作放在页面标题右侧，不占用列表底部空间
- 已完成记录默认分批展示 100 项，封面使用懒加载；进行中和失败记录始终完整展示
- 失败状态使用红色标识、错误说明和浅色重试按钮
- 空记录状态提供明确说明和返回检索入口

### 配置页

- 使用登录、下载设置和日志三个语义标签页
- 登录状态、刷新动作和账号字段放在同一任务容器内
- 清除登录信息放在更多操作菜单中
- 下载和日志设置使用自动保存，不保留显式保存按钮
- 自动保存仅显示“未保存”或“保存失败”，不显示“已保存”和“保存中”
- 所有 `tab` 的 `aria-controls` 始终指向已挂载的 `tabpanel`

## 12. 动效与反馈

动效服务于操作反馈、状态变化和空间关系，不用于装饰页面或延迟高频操作

- 页面导航、标签切换和键盘触发的高频操作保持即时，不添加进出场动画
- 可点击命令使用 `motion-pressable` 提供 160ms 的轻微按压反馈；disabled 状态不位移
- Toast 和账号操作浮层从自身来源方向进入，使用透明度与小幅位移或缩放，不从 `scale(0)` 开始
- 下载进度通过 `scaleX` 平滑过渡填充，不使用持续脉冲或布局属性动画；加载 spinner 保持较快、稳定的线性转动
- 常规 UI 动效控制在 300ms 内，进入和反馈优先使用 `--motion-ease-out`，屏幕内位移才使用 `--motion-ease-in-out`
- 动态界面优先使用可中断的 CSS transition；只动画 `transform`、`opacity` 等低成本属性，避免 `transition-all`
- hover 位移和缩放保持克制，不缩放正文，避免文字发虚和布局视觉跳动
- `prefers-reduced-motion: reduce` 下移除位移、缩放和持续旋转，仅保留有助于理解状态的短透明度或颜色过渡

## 13. 响应式与可访问性

- 默认窗口为 `1200 × 800`
- 最小窗口为 `900 × 600`
- 两种尺寸均不得出现页面级横向滚动、主要操作不可见或控件重叠
- 窄窗口优先调整列数、换行和间距，不缩小主要正文强行容纳
- 主要流程保持键盘可用，焦点状态可见
- 配置页的语义标签支持方向键、Home 和 End 导航
- `aria-controls`、`aria-labelledby` 等 ID 引用必须指向存在的元素
- 颜色不能作为状态的唯一表达
- IPC 订阅在组件卸载时清理
- 外链、本地目录和系统能力通过 preload 的受限接口调用

## 14. UI 修改检查清单

- 是否复用了现有 `apple-*` 令牌和组件模式
- 是否出现重复主动作、卡片套卡片或过多小字
- hover 是否只用于真正可交互的内容
- 动效是否有明确用途、低于 300ms，并使用具体过渡属性而非 `transition-all`
- 高频导航和键盘操作是否保持即时，reduced motion 是否移除了非必要移动
- 自动保存是否避免“已保存”和“保存中”闪烁
- loading、error、empty、disabled 和长内容状态是否完整
- 键盘、焦点、标签关系和图标名称是否可用
- `1200 × 800` 和 `900 × 600` 是否无横向溢出
- 是否运行受影响测试、web typecheck、Lint、构建和 `git diff --check`
