# 全局用户反馈与无静默失败规范

## 目标

为渲染进程提供统一 Toast、字段校验和最终错误兜底。任何由用户点击、提交或路由进入触发的失败，都必须立即给出不懂代码也能理解的中文提示；日志继续保留诊断信息，但界面不得直接展示技术异常。

## 反馈分层

- 字段输入不合法：在对应字段旁显示错误，并关联 `aria-invalid`、`aria-describedby`。
- 短时操作失败或成功：使用全局 Toast。
- 页面无法继续但可以恢复：页面内持久错误，同时首次出现时显示 Toast。
- React 渲染崩溃：显示恢复页；未捕获的全局错误或 Promise 拒绝显示通用错误 Toast。

允许不提示的情况仅限：用户主动取消确认框或目录选择、已有明确说明的禁用控件、调度器/缓存/过期请求等内部控制流，以及界面已显示“处理中”的重复点击保护。

## Toast 行为

- 同时最多显示 3 条；相同内容 2 秒内合并并刷新计时。
- 成功和信息默认 4 秒，警告和错误默认 7 秒。
- 鼠标悬停或键盘焦点进入时暂停倒计时。
- 错误使用 `role="alert"`，其他类型使用 `role="status"`。
- 支持关闭按钮和站内恢复操作，操作链接使用 Hash 路由。

## 文案安全

界面不得显示 `Error invoking remote method`、`IPC`、`Error:`、堆栈、本地路径、完整 URL、HTTP 状态码或 `Cookie`。账号相关问题统一称为“登录状态”或“登录信息”。原始异常只写入现有日志通道。

## 关键业务验收

- 搜索：编号仅接受 1 至 12 位数字或可解析的 Wenku8 作品链接；标题/作者必填且最多 100 字；无结果显示明确空状态；非法运行时搜索类型也必须结束 loading 并提示。
- 作品详情：缺失或非法编号不调用接口；无作品、无卷、下载前状态缺失都必须提示并提供恢复路径。
- 配置：账号、密码、封面索引和日志数值约束使用字段提示；保存、登录、选目录、打开目录失败使用友好 Toast。
- 下载：重试失败、打开目录失败、下载失败必须提示；历史错误需要迁移为安全文案。部分资源失败只能以“完成但有提醒”结束，不能伪装成完全成功。
- 主进程：空章节、没有可写内容、批量图片全部失败必须拒绝；封面或插图部分失败应返回安全 warnings，由渲染进程展示。

## 类型约束

共享下载结果为 `{ status, message, warnings? }`。完成任务可持久化单条安全 `warning`。不得为了本功能引入通用 IPC 结果信封或新的第三方提示依赖。
